# Data Audit

Master prompt §7. What the organisers actually gave us, measured rather than
assumed.

Source: `data/raw/DataSet.xlsx` (read-only, SHA-256 verified unmodified by the
release gate) and `Description.xlsx`. Generated by `muleguard.cli.audit_data`;
full per-feature tables in `artifacts/reports/data_profile.csv` and
`artifacts/reports/leakage_audit_table.csv`. Method detail and the retired-run
narration: `docs/DATA_AUDIT_REPORT.md`.

**Neither workbook is ever written to.** Every derived file is a copy.

---

## 1. Shape and target

| Item | Value |
|---|---|
| Rows (accounts) | **9,082** |
| Columns including target | **3,925** |
| Target | `F3924` — 1 = labelled mule/suspicious, 0 = not labelled |
| Positives | **81** |
| Negatives | 9,001 |
| Null targets | 0 |
| Prevalence | **0.8919 %** (≈ 1 : 111) |

One row per account. **No transaction table, no counterparty column, no
sender/receiver, no edge list.** Everything is pre-aggregated into fixed windows.
That single fact determines what this system can and cannot do, and is why the
Graph Adapter reports `UNAVAILABLE` rather than inventing relationships.

### Why 81 positives dominates every decision

Every modelling choice downstream traces back to this number. With 81 positives
split 64 dev / 17 locked test:

- a single-split test fold holds ~16 positives, so one case moves recall by ~6
  points — which is why we use **5 folds × 3 repeats** and report a std;
- the measured **seed-noise floor is 0.0905 PR-AUC** — differences smaller than
  that are not differences;
- resampling (SMOTE) would interpolate synthetic mules between 81 real ones in a
  3,924-dimensional space, manufacturing accounts that do not exist. Rejected;
- hundreds of automatically generated ratio features would guarantee that some
  fit the 81 by chance. We built **13** meta-features, all domain-justified.

## 2. Data quality

| Item | Value |
|---|---|
| Missing cells (features) | 9,847,086 — **27.63 %** |
| Columns with any missing | 3,835 of 3,924 |
| Constant columns | 359 |
| Quasi-constant (≥ 99 % one value or missing) | 1,078 |
| Exact duplicate columns | 977 |
| Dtypes | 3,916 Float64, 6 String, 1 Date, 1 Datetime |
| Index-like columns detected | `__UNNAMED__0` |

**More than a quarter of all cells are empty**, and roughly a third of the
columns are constant, quasi-constant or exact duplicates of another column. The
usable width of this dataset is far smaller than 3,924.

Missingness is treated as **information, not as a defect**. A null in a rail
column means the account did not use that rail. Meta-features that cannot resolve
their inputs degrade to **null, not zero** — a fabricated 0 would be read by the
model as a real measurement of "no activity".

## 3. The two things that would have destroyed the submission

### 3.1 `__UNNAMED__0` — the index column

| Feature | Target corr | Single-feature CV PR-AUC |
|---|---:|---:|
| `__UNNAMED__0` | 0.1628 | **1.0000** |

A cross-validated PR-AUC of **1.0** from the row index. The file is sorted with
labelled mules grouped, so row position perfectly reconstructs the target. Any
pipeline that reads column A as a feature scores a flawless local number and
collapses on any file whose rows arrive in a different order.

Quarantined as `INDEX_OR_ID`.

### 3.2 `F3912` — `FRAUD_SUSPECTED`

| Feature | Target corr | Single-feature CV PR-AUC |
|---|---:|---:|
| `F3912` | **0.9691** | 0.9433 |

`Description.xlsx` identifies it as a **resolution status flag** — it records the
outcome of the investigation. It is not a predictor; it is the answer written
back into the input.

Measured ablation (`artifacts/metrics/leakage_ablation.csv`):

| Variant | OOF PR-AUC | Status |
|---|---:|---|
| without `F3912` | 0.61416 ± 0.04737 | **ACCEPTED (leakage-free)** |
| with `F3912` | 0.94190 ± 0.01186 | **REJECTED — never used** |

**+0.32773 PR-AUC from one column.** We publish this precisely because it is the
trap: on this dataset a spectacular headline number is more likely to be evidence
of a quarantine failure than of modelling skill.

Twelve further columns are quarantined on the same principle — see
`docs/FEATURE_AVAILABILITY_AUDIT.md` for all 13 with reasons.

### 3.3 The genuine signals are weak

Excluding the two above, the strongest honest correlations are ~0.18
(`F2506`/`F2507`) with single-feature CV PR-AUC around **0.012** — barely above
the 0.0089 prevalence floor. **No single feature solves this problem.** The
signal is in combinations, which is exactly why a tree ensemble over a
stability-selected compact set is the right tool and a rules engine is not.

| `F3892` `GENDER` | String | 3 | **28.61 %** | M 5,007 · F 1,416 · O 61 |

### `F2230` is a trap disguised as a time column

Look at the distribution again. **Every one of the 9,001 negatives sits in
2025-10.** All 81 positives sit in 2025-09, 2025-11 or 2025-12. The snapshot
month reconstructs the label with fidelity **1.0**.

Consequence, stated plainly: **out-of-time validation is impossible on this
dataset**, and Track C is published as `NOT_VALID` rather than quietly dropped or
reported with a fake number. A team that splits by `F2230` gets a perfect score
and learns nothing. See `docs/HIDDEN_VALIDATION_STRATEGY.md` §4.

`F3892` (gender) is additionally **excluded by fairness policy** — see
`docs/FAIRNESS_AND_SENSITIVE_FEATURE_AUDIT.md`.
