## Verified behaviours

- **Determinism:** identical request → bit-identical calibrated risk and tier
  (harness rescore check + pytest + release-gate check).
- **Model lifecycle:** bundle loaded once at startup (warmup in FastAPI
  startup hook); `/health/ready` fails 503 until it is loaded; model version +
  SHA-256 served by `/v1/model` and matched against the manifest.
- **Validation:** Pydantic schemas on every route; masked account references
  enforced; target column in a request → 422; missing selected features →
  422 `SCHEMA_ERROR` (silent zero-fill is structurally impossible); malformed
  JSON → 422; batch cap 500; upload cap 60 MB.
- **Observability:** correlation IDs accepted/propagated; structured logs
  with secret redaction; append-only audit events for scores, decisions,
  reports and batch progress.
- **Error semantics:** 404 unknown case, 409 case without score payload,
  413 oversized upload, 422 validation, 429 rate limit, 503 no model.
- **No test labels at inference; no LLM in the scoring path** (code-level
  greps + tests).

## Graceful failure

Missing bundle → readiness stays 503 with a clear message (run.sh surfaces
the log tail and exits non-zero). Ollama outages trip a circuit breaker and
never propagate to scoring. SQLite lock contention is bounded by a 15 s
busy timeout; batch scoring chunks at 500 rows keeping peak RAM flat.
